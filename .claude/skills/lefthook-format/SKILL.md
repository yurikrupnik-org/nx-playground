# Formatters in git hooks (lefthook)

`lefthook.yml` at the repo root is the only hook config; `.git/hooks/*` are
generated by `lefthook install` (per clone — `lefthook check-install` exits 1
when missing; any `lefthook run` also auto-installs unless `--no-auto-install`).
Every formatter already has a task leaf (`fmt-<eco>` rewrites, `fmt-check-<eco>`
gates, aggregated by `task fmt` / `task fmt-check` in `scripts/tasks/flows.yml`).
Hooks REUSE those tools; they never introduce a formatter the tasks do not run.

## 1. Pick the runner — detect, never add

| Repo has | Runner in `run:` | Where |
| --- | --- | --- |
| `Taskfile.yml` | `task <leaf>` | nx-playground (this repo) |
| `justfile` | `just <recipe>` | kcl-packages, dotconfig |
| neither | the formatter binary | any other repo |

Never add a `justfile` here (the old `ci.just` was retired for `task`) or a
Taskfile to a `just` repo — a second runner is a second convention. A new
formatter is a new ecosystem: `fmt-<eco>` + `fmt-check-<eco>` leaves appended to
`fmt`/`fmt-check` first (flows.yml rule), `skill://cncf-manager` if the tool is
not already in `docs/tooling/registry.toml`, and only then a hook job.

## 2. Pick the hook — the split is the whole design

- **pre-commit = fixers over `{staged_files}`**, with `glob` and
  `stage_fixed: true`. Never a whole-tree command.
- **pre-push = read-only whole-tree gates** through the runner:
  `task fmt-check`, `task fmt-check-rust`, `bunx biome ci .` (`just check` in
  the `just` repos). A gate never writes.
- **CI never uses lefthook**; it calls the same task leaves.

Behaviour verified on lefthook 2.1.14 — design against it, not against memory:

- `glob: "*.rs"` matches at any depth; no `**/` needed.
- No staged file matches the glob → the job is skipped ("no matching staged
  files"). A job without `glob` and without `{staged_files}` always runs.
- `{staged_files}` shell-quotes each path; `a/b/one two.txt` arrives as one arg.
- `stage_fixed: true` hides unstaged hunks of the staged files while jobs run
  and restores them after: the commit gets the formatted staged content, the
  unstaged edits survive.
- A whole-tree fixer with `stage_fixed` commits only the staged files but
  REWRITES EVERY OTHER FILE in the working tree — unrelated WIP gets reformatted
  and the tree is left dirty. That is why fixers take `{staged_files}`.
- `root: "dir/"` runs the job with cwd `dir/` and makes `{staged_files}`
  relative to it (`./x/a.p`).
- Jobs in one `parallel: true` block race when two fixers touch the same file.
  Put fixers in a `group: { piped: true, jobs: [...] }`; checks may run parallel.

## 3. Passing files through a runner

Direct binary is the default for pre-commit. If the fixer must live behind the
runner (shared flags, several steps), the file list has to survive it:

```just
# just: `*files` + `{{files}}` word-splits — `sp ace.md` becomes two args.
[positional-arguments]
fmt-files *files:
    rumdl fmt "$@"
```

```yaml
# task: `task <leaf> -- {staged_files}`; go-task keeps the quoting in
# {{.CLI_ARGS}}, and {{.CLI_ARGS_LIST}} gives one item per file.
fmt-docs-files:
  cmds:
    - rumdl fmt {{.CLI_ARGS}}
```

The existing `fmt-*` leaves IGNORE `CLI_ARGS`: `task fmt-docs -- {staged_files}`
silently formats the whole tree (see §2). Add a `-files` leaf beside the
whole-tree one; never change the existing leaf, `task fmt` and CI depend on it.

## 4. Staged-file form of each formatter this repo runs

| Tool | `glob` | pre-commit `run:` | Trap |
| --- | --- | --- | --- |
| biome | `*.{js,jsx,ts,tsx,json,jsonc,css}` | `bunx biome check --write --linter-enabled=false --no-errors-on-unmatched {staged_files}` | Without `--write`, `stage_fixed` has nothing to stage. Without `--no-errors-on-unmatched`, a staged file under a `!` entry in biome.json `files.includes` exits 1. |
| rustfmt | `*.rs` | `rustfmt --edition 2024 {staged_files}` | No rustfmt.toml: bare `rustfmt` = edition + style_edition 2015, disagreeing with `cargo fmt`. rustfmt also formats out-of-line `mod` children. `cargo fmt --all` is whole-tree → pre-push only. |
| cargo-sort | — | none | Workspace-level; `task fmt-check-rust` on pre-push. |
| ruff | `*.py` | `ruff format {staged_files}` | Config resolved per file; `task fmt-py` goes through nx, not usable per file. |
| kcl | `*.k` | `kcl fmt {staged_files}` | Indent width comes from `.editorconfig`; without its `[*.k] indent_size = 4` section `kcl fmt` re-indents every file to the repo-wide 2. `task fmt-kcl` is scoped to `./scripts/kcl/...`: `./...` from the root walks node_modules and target/ (14s). |
| rumdl | `*.md` | `rumdl fmt {staged_files}` | `respect-gitignore` does not apply to explicitly named files. |
| buf | `*.proto` | `buf format -w {staged_files}` with `root: "manifests/grpc/"` | buf.yaml lives in manifests/grpc; outside it buf falls back to defaults. |
| typos | none | `typos --force-exclude --write-changes {staged_files}` | Without `--force-exclude`, explicit paths bypass `_typos.toml` `extend-exclude` (vendored htmx.min.js: 245 findings vs 0) and `--write-changes` rewrites vendored code. Runs LAST, as in `task fmt`. |

Template:

```yaml
pre-commit:
  jobs:
    - name: fmt
      group:
        piped: true          # fixers share files; typos last
        jobs:
          - name: rustfmt
            glob: "*.rs"
            run: rustfmt --edition 2024 {staged_files}
            stage_fixed: true
          - name: typos
            run: typos --force-exclude --write-changes {staged_files}
            stage_fixed: true
pre-push:
  jobs:
    - name: fmt-check
      run: task fmt-check
```

## 5. Verify

1. `task hooks-check` (`lefthook validate`) — config schema.
2. `lefthook run pre-commit --all-files --fail-on-changes --no-stage-fixed` —
   every fixer over the tree; exit 1 plus a diff means a fixer disagrees with
   the tree. It WRITES files: run on a clean tree, `git diff` after.
3. Stage one file per changed glob (one with a space in its path, one with an
   unstaged hunk) and `git commit`; confirm the commit holds formatted content
   and the unstaged hunk is still in the working tree.
4. `task fmt-check` — the hook and the gate must agree.

## Rules

- Never bypass: `--no-verify` and `LEFTHOOK=0` are the same act. A failing hook
  is fixed or reported, not skipped.
- A hook runs a SUBSET of what the task gates run, never a different tool or
  different flags than the matching `fmt-*` leaf.
